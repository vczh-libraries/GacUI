### Composition-change event contract

- The intended class name is `GuiGraphicsComposition`, in `Source/Application/GraphicsCompositions/GuiGraphicsComposition.cpp`. Declare `CompositionUpdateType` and the new event-argument type immediately above `GuiWindow` in `Source/Application/Controls/GuiWindowControls.h`. Follow the existing `GuiEventArgs` / `Description<T>` convention and expose `ChildCompositionUpdated` as a typed graphics event, associated with the window's bounds composition.
- `parent` is the composition whose child collection changed; `child` is the directly inserted, removed, or reordered child. The event belongs to that composition's owning `GuiWindow`, including a logical hosted window. It is a notification, not a cancelable request, and its pointers do not transfer ownership.
- Notify once after a successful structural change and its existing parent/control/host bookkeeping have completed. Failed insert/remove/move calls, detached-tree mutations, and `MoveChild` to the existing index produce no event. `AddChild` already delegates to `InsertChild`, so it must not add a second notification.
- Capture the owning window before removal disconnects the subtree. A removal notification exposes the old parent and live removed child while the parent's collection already excludes that child. Insertion and move notifications expose the resulting collection order. Resolve the owner from the parent/host context, not from the removed child's now-cleared control ancestry.
- Reparenting is the existing remove followed by insert, with one notification to each affected window. Attaching a populated subtree produces one notification; the UIA listener scans that subtree internally to discover its semantic descendants. Such scanning does not recursively raise `ChildCompositionUpdated`.
- Event arguments are valid for synchronous notification only. Deferred UIA work must retain provider/lifetime state rather than raw composition pointers. Account for reentrant handlers and construction/destruction: do not deliver through an incompletely constructed or already destructed `GuiWindow` event, and do not access a removed child after subscribers may have deleted it.
- Register the event, enum, and argument fields using the existing patterns in `Source/Reflection/TypeDescriptors/GuiReflectionPlugin.h`, `GuiReflectionControls.cpp`, and `GuiReflectionEvents.cpp`. This is a cross-platform public event even though the provider consuming it is Windows-only. Regenerate both architectures' metadata as required by `Project.md`.

### Windows listener, threading, and lifetime

- The four named public setup functions delegate to `SetupWindowsGDIRendererInternal` in `Source/PlatformProviders/Windows/GDI/WinGDIApplication.cpp` and `SetupWindowsDirect2DRendererInternal` in `Source/PlatformProviders/Windows/Direct2D/WinDirect2DApplication.cpp`. Raw renderer routes also pass through these functions; they must not expose a fabricated semantic GacUI tree when no local `GuiApplication` owns it.
- `IWindowsForm::InstallMessageHandler` retains a `Ptr<INativeMessageHandler>`, whereas controller callback registration uses a raw listener pointer. Give `uiaListener` one owning `Ptr` and pass that ownership through message-handler installation; do not imitate the existing native listener's stack allocation or create a second owning `Ptr` from `.Obj()`.
- If teardown uses `UninstallMessageHandler`, fix its existing removal bug in `Source/PlatformProviders/Windows/WinNativeWindow.cpp`: it computes `index` but passes `handler` to `messageHandlers.RemoveAt`, which must receive `index`. Treat this as a narrow prerequisite to using the existing handler API, and verify removal with multiple installed handlers.
- In hosted mode, observe both actual native-window lifecycle and hosted logical-window lifecycle. The real controller owns the HWND; the hosted controller reports virtual subwindows. Resolve all hosted providers to the one actual HWND, attach logical windows beneath the main root, and preserve their own descendants and semantics. Ordinary windows retain their separate HWND roots. Do not treat a virtual `INativeWindow` as an `IWindowsForm`.
- `GuiWindow` creates its native window before `SetNativeWindow` and `GuiApplication::RegisterWindow` finish. Install the message hook when notified, but defer semantic binding until construction has completed, checking that the recorded window is still alive. Seed existing windows and attached subtrees before exposing their providers. Retain associations for teardown because native destruction occurs after the application has unregistered the `GuiWindow`.
- Handle `WM_GETOBJECT` for `UiaRootObjectId` through `INativeMessageHandler::AfterHandle`, setting the result and `skip` so the default procedure does not overwrite it; `BeforeHandle` cannot supply that result. Compare the object identifier using the documented signed convention. Return `UiaReturnRawElementProvider` only for a live, initialized root, and leave other object IDs to their existing handling. Use `UiaHostProviderFromHwnd` for the actual HWND root's host provider, not every semantic child. See [WM_GETOBJECT handling](https://learn.microsoft.com/en-us/windows/win32/winauto/handling-the-wm-getobject-message).
- GacUI objects are UI-thread-only, but these Windows setup functions initialize COM as MTA. `ProviderOptions_UseComThreading` alone therefore does not marshal calls to the GacUI thread. Dispatch reads and writes through a defined UI-thread boundary, execute directly when already on that thread, and avoid holding locks while waiting or raising UIA events. UiaList and script clients should make calls and manage subscriptions on a windowless MTA worker, following [UIA client threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading).
- `IInvokeProvider::Invoke` must queue the action and return without waiting through modal UI. Validate the target's lifetime again when the queued action executes; avoid a blocking UI invocation that deadlocks the inspector while a dialog is open. See [Invoke requirements](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-iinvokeprovider-invoke).
- Keep hook state separate from exposed-tree membership and COM wrapper lifetime. Reuse existing internal-property/lifetime facilities to own per-object state; hook once, ignore ordinary callbacks while detached, and invalidate destroyed targets even when clients retain wrappers. Seed hooks independently of client enumeration. Reattachment, theme replacement, and list recycling must not duplicate subscriptions or make an old provider refer to a different object at a reused address.
- Return UIA's documented unavailable/unsupported/disabled results for those expected states; do not dereference stale controls or advertise a pattern whose operations are only stubs. Retire providers during teardown without returning them again to reentrant `WM_GETOBJECT` requests. `UiaDisconnectProvider` cannot run inside a synchronous `SendMessage` call; defer that COM cleanup when necessary, after marking the target unavailable. See [provider disconnection](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiadisconnectprovider).
