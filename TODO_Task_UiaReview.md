# GacUI Windows UI Automation requirements review

This is a review backlog, not an implementation plan or a claim of UIA conformance. It compares the source at `e242162299e8efde6c3a5e3be400607704bbcc18` with Microsoft Learn's Win32 UI Automation documentation, consulted on 2026-09-18. No provider code was changed and no application was executed for this review.

The [current implementation inventory](.github/KnowledgeBase/KB_GacUI_Design_UIAutomation.md) belongs in the knowledge base. This document records discrepancies and the observations needed to resolve them. All checkboxes remain open for the later review, including cases where the source already contains the expected mechanism.

- **Source gap** means the inspected code demonstrably omits or differs from a documented behavior. It does not mean a live client failure was reproduced.
- **Verify** means an implementation exists, but its complete behavior, applicability, or interaction with UIA's host provider needs checking.
- **Project requirement** identifies GacUI-specific architecture or acceptance criteria; it is not attributed to Microsoft.
- **Required**, **conditional**, **never**, and **typical tree** preserve the strength of the Microsoft documentation. A typical-tree diagram alone does not establish that every optional intermediary is mandatory.

## Semantic tree contracts and source comparison

This inventory covers all 31 standard control types currently returned by `WindowsUIAutomationNode::Role`. Pattern names below mean their corresponding provider interfaces; control types are semantic roles, not COM interfaces. Common metadata, event and lifetime obligations are reviewed separately below.

The other standard roles listed by Microsoft are AppBar, Custom, Hyperlink, Image, SemanticZoom, Spinner, StatusBar, Table, Thumb and TitleBar. `Role` does not currently return these roles. This is a scope observation, not a blanket requirement to implement them: applicability depends on the controls and semantics actually offered, including content embedded in documents and elements supplied by the native host provider. [Standard control type identifiers](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-controltype-ids)

## Tree and ownership verification checklist

### T1. Combo dropdowns, submenus and context menus

- [ ] **Source gap:** make the review's expected combo subtree explicit: the dropdown list and its items must be reachable from the owning combo. Native top-level placement of a popup is independent of semantic UIA ownership. In `Semantic`, `Children`, `Parent`, `IsRoot`, and `UiaCombo` currently do not establish this ownership. In ordinary mode the popup is a fragment root; in hosted mode it is a child of the main window. Verify both directions of every parent/child/sibling link and ensure the popup appears only once. [ComboBox tree](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportcomboboxcontroltype)
- [ ] **Source gap:** perform the same ancestry review for nested menus and split-button menus. Reserve the desktop/top-level exception for genuine context menus. Verify opener -> submenu -> item paths through several levels, closed-state removal, reopen identities, nested combos in menus and menus inside hosted dialogs. [Menu ownership](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportmenucontroltype), [MenuItem subtree](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportmenuitemcontroltype), [SplitButton subtree](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportsplitbuttoncontroltype)
- [ ] **Documentation discrepancy to resolve:** Menu's page says Menu is included in both views; MenuItem's typical content diagram omits the submenu Menu wrapper. SplitButton's typical table and example also differ. Record which content-view representation is accepted and why; these inconsistencies do not remove the owner/submenu relationship in the control view.
- [ ] **Verify:** combo `Selection.GetSelection`, item `SelectionContainer`, parent ancestry and `IsSelected` must identify the same logical combo/list selection before opening, while open and after closing. `UiaSelect` currently changes list selection before rejecting combo removal. Exercise `RemoveFromSelection` and `AddToSelection` and verify rejected calls do not partially alter the selection. Capture selection and expansion events as well as return codes.

### T2. Other popup owners and split-button behavior

- [ ] **Source gap:** inspect tooltip owner ancestry, nonfocusable tooltip content exclusion and owner HelpText. Review `GuiTooltip`'s inherited Window/Transform support against its actual capabilities; `UiaWindowEvent` chooses tooltip events even though Window may also be advertised. Verify the events needed by the advertised patterns. [ToolTip contract](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporttooltipcontroltype)
- [ ] **Verify:** for each SplitButton returned by `Role`, acquire both Invoke and ExpandCollapse; find the distinct sub-button in control view; invoke the default command without opening the menu; expand without running the default command. Cover checked/grouped toolbar buttons and ribbon variants. `Supports` and the blanket button-child suppression need reviewing together.
- [ ] **Verify:** `GuiRibbonGroup`, `GuiRibbonGroupMenu`, `GuiRibbonGallery` and responsive ribbon overflow retain understandable group/owner relationships when their content moves between ordinary compositions and popup windows. Determine which controls actually have expand/collapse behavior before requiring that pattern.

### T3. Data-grid visualizers and editors stay inside their cell

- [ ] **Existing mechanism to verify:** `DefaultDataGridItemTemplate::NotifyOpenEditor` adds the editor template to the existing cell and hides the visualizer. `Semantic::Children` for a cell enumerates the opened editor, otherwise the cell's visualizer controls; `Parent` recognizes a cell under `DefaultDataGridItemTemplate`. Verify `DataGrid -> row -> cell -> visualizer controls` changes to `DataGrid -> row -> same cell -> editor controls`, and back on close. Retain the cell's RuntimeId, GridItem coordinates, ContainingGrid and column-header relationship. [DataItem children](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportdataitemcontroltype)
- [ ] **Verify:** repeat with text, checkbox, combo and date editors; nested controls; a visualizer decorator; an editor template whose root itself has an associated control; and a custom item template. `UiaCollectChildren` starts at children, and `Parent` recognizes a specific default table shape, so these cases cannot be inferred from the default text editor. Require exactly one active editing subtree and no stale visualizer value duplicated beside it.
- [ ] **Verify:** the dropdown of a combo editor must remain below that combo, which remains below its cell. The complete path is grid -> row -> cell -> combo -> dropdown content. T1's current popup behavior breaks that path even though the editor itself has the correct cell parent.
- [ ] **Verify:** retain editor/visualizer provider references across commit, cancel, sort/filter, row removal, column rebuild, offscreen recycling and theme refresh. Removed controls must become unavailable; replacement controls must navigate back to the current cell. Inspect structure events on the affected semantic subtree, not only on the top window.

### T4. Grid coordinate, selection and editing contracts

- [ ] **Source difference:** `UiaSelectedChildren` recurses only into TreeNodes. A data grid's `GetSelection` therefore enumerates selected row Items, while cell `IsSelected` uses `GetSelectedCell`. Review whether the advertised selection unit is row or cell, and make `GetSelection`, `SelectionContainer`, row/cell `IsSelected`, focus and selection operations mutually consistent. The current suite does not assert that the selected cell is returned by container Selection.
- [ ] **Verify:** `Grid.GetItem`/Table relationships must remain correct with zero rows/columns, horizontal scrolling, reorder, resize, sort/filter and switching a list view out of Detail. Cells currently have unit spans; rows do not expose GridItem/TableItem. Determine the required row-level metadata for the chosen row/cell representation. [DataGrid patterns](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportdatagridcontroltype)
- [ ] **Conditional source gap:** editable primary text on a DataItem requires Value, but row/cell `Supports` never returns Value. Decide which cells and parent item containers meet that condition; opening a child Edit via Invoke is a separate capability. Verify typed values, validation, read-only columns and string conversion without assuming every custom editor has a string-settable value. [DataItem Value](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportdataitemcontroltype), [Value conventions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingvalue)
- [ ] **Verify:** cell Invoke queues `SelectCell(..., true)` and ignores its Boolean result. Editing requires an available item template in the grid implementation. Attempt to edit an offscreen cell, first directly and then after VirtualizedItem.Realize/ScrollItem.ScrollIntoView; record whether the action occurs and whether a success result can be a no-op. Check custom editor failure/validation without changing application semantics.

### T5. Tab page association and hit testing

- [ ] **Verify:** compare the selected TabItem's child controls with the documented Pane association; where a distinct page Pane is appropriate, confirm it is a child or associated through ControllerFor. Current generic traversal supplies neither a dedicated Pane nor that relationship. Existing `Page` tests accept direct descendants and do not establish the complete control-view contract.
- [ ] **Source risk to verify:** `Composition` gives TabItem the header rectangle, while its children come from the page content. `UiaHitTest` only descends into a child when its rectangle contains the point. Hit-test buttons/editors in the selected page body from the fragment root, especially with nested tabs; ensure a point is not rejected merely because it lies outside the header. [TabItem page relationship](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporttabitemcontroltype)
- [ ] **Verify:** select a clipped tab header, delete the selected/last page, navigate overflow headers, and switch responsive ribbon tabs. Record orientation, focusability, selected item and conditional Scroll availability.

### T6. Calendar hierarchy and headers

- [ ] **Source differences to verify:** the current Calendar directly owns header/day nodes, and calendar headers have no composition/bounds. Compare this with the DataGrid/Header structure in Microsoft's control view. Record an accepted control/content hierarchy and accurate visible header geometry.
- [ ] **Verify:** a date picker using an alternative template still supplies required Grid. Check day name/date values, month spillover, current selection, year/month combo ownership, six-by-seven coordinates and header relations. Preserve distinct identities when the displayed month changes. [Calendar contract](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportcalendarcontroltype)

### T7. Lists, tree items and content filtering

- [ ] **Source gap:** generic list-item template controls remain content elements beneath ListItem. Review content filtering or a more appropriate DataItem role for rich items; retain useful child controls in control view without violating ListItem's content-leaf contract. This is distinct from the deliberate DataGrid cell-child hierarchy. [ListItem tree](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportlistitemcontroltype)
- [ ] **Conditional source gaps:** command-capable list/tree items have no Invoke path; editable item text has no Value path; custom tree template controls are not enumerated. Identify actual control behaviors requiring these patterns and metadata, including dynamic ItemStatus/ItemType. Do not infer every item is invokable solely because a double-click event exists. [ListItem patterns](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportlistitemcontroltype), [TreeItem patterns](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporttreeitemcontroltype)
- [ ] **Verify:** tree collapse removes descendant navigation while scroll-offscreen retains logical nodes; expand and ItemContainer searches recover the intended model item. Verify shared SelectionContainer, parent/sibling reciprocity, hidden-node selection and model replacement without realizing every item.

### T8. Containers and smaller controls

- [ ] **Verify:** radio SelectionContainer must identify the actual mutually exclusive group, including two groups with one composition parent. Current fallback parent has no general Selection provider and can combine unrelated groups. [RadioButton relationships](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportradiobuttoncontroltype)
- [ ] **Verify:** pure presentation `GuiControl` wrappers should not appear as meaningful Pane nodes. Examine empty wrappers, decorators and custom templates; flatten compositions without losing semantic controls. [Pane restrictions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportpanecontroltype)
- [ ] **Verify:** ordinary and hosted windows retain meaningful owned/modal ordering and native host integration. Do not apply submenu ownership rules to independent dialogs. Review standalone scrollbar versus slider roles and the control-view buttons/thumb in tracker templates; check the actual operations that a custom theme exposes.

## Text providers and editing

### X1. Labels, read-only content and password transitions

- [ ] **Source gap:** all `GuiDocumentCommonInterface` controls and combos return an empty Name, and `Property` has no LabeledBy/HelpText implementation. Verify an application can expose a stable field/document label without using the edited value. A nearby label in another branch does not itself create a UIA label relationship. [Edit naming](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporteditcontroltype), [Document naming](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportdocumentcontroltype)
- [ ] **Verify:** single-line and multiline Value setters honor `ViewOnly`, `Selectable` and `Editable`, control disablement and modal-window disablement. Text selection remains possible for selectable read-only content. Evaluate editable `GuiDocumentLabel`/`GuiDocumentViewer` configurations that expose Text but lack Value. Text ranges themselves provide selection/navigation, not a general insert/delete API. [Value conventions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingvalue), [Text object model](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-understandingtheuiautomationtextobjectmodel)
- [ ] **Verify:** password `get_Value` fails; `GetPropertyValue(ValueValue)` currently leaves `VT_EMPTY` with `S_OK`; Text availability becomes false and retained ranges fail `Read`. Exercise both direct client pattern getters and `GetCurrentPropertyValueEx`, including a previously unprotected field changing to password mode. No Name, Value event, cached old-value payload, child node or retained range may expose protected text after that transition. Reconcile generic Edit Text support with the explicit protected-content rule instead of enabling plaintext Text access. [Edit protected values](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporteditcontroltype), [Microsoft TextPattern security guidance](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-textpattern-overview#security)

### X2. Range identity, movement and selection

- [ ] **Verify:** `WindowsUIAutomationTextSnapshot` preserves UTF-16 text, maps CR/LF and surrogate pairs to valid carets and emits object markers. Test empty/one-character documents, paragraph boundaries, run boundaries, supplementary characters, combining marks, emoji sequences, CJK and bidirectional text. `Boundaries(Word)` uses `iswalnum`/`iswspace`; establish whether its word/character units match the editor's navigation. Page currently falls back to document-sized boundaries. [Text units and normalization](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange)
- [ ] **Verify:** `Normalize` infers a single changed interval by common prefix/suffix. Retain several overlapping and degenerate ranges through insert/delete/replace, multiple disjoint edits between queries and document replacement. Verify Clone independence, endpoint crossing, limits and wrong-document rejection. Model replacement deliberately invalidates existing ranges; record this behavior explicitly.
- [ ] **Source risk to verify:** range Select checks control enablement but not the native-window modal enabled state; RemoveFromSelection does not perform that control-enabled check. Add/Remove also impose stricter range-equality conditions. Test selection/caret operations on disabled/modal-blocked controls, degenerate ranges outside the current selection and single-selection extension/truncation. [Text selection conventions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange)

### X3. Visible ranges, geometry and scrolling

- [ ] **Source gap:** range `ScrollIntoView` changes only the vertical position of a `GuiScrollView`; it does nothing for `GuiSinglelineTextBox`/`GuiDocumentLabel`. Verify horizontal overflow and both alignment requests; the resulting range must actually become visible along both axes where scrolling is available. [ScrollIntoView](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-itextrangeprovider-scrollintoview), [Text visibility conventions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange)
- [ ] **Verify:** compare `RangeFromPoint`, `GetVisibleRanges`, caret positions and bounding rectangles with rendering at multiple DPI scales and hosted offsets. Include wrapped lines, partial clipping, an empty document, zero-length ranges, surrogate pairs and RTL. The current rectangle merger works from adjacent caret rectangles; test that it neither includes unrelated lines nor loses RTL extents.

### X4. Embedded controls, links and text attributes

- [ ] **Source difference:** `GetEnclosingElement` always returns the document node, while the documented result is the nearest enclosing semantic element where a more specific embedded child contains the range. `RangeFromChild` always returns a one-marker range. Verify text-bearing embedded controls, images, nested objects and children returned from a partial text range. [GetEnclosingElement](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-itextrangeprovider-getenclosingelement)
- [ ] **Verify:** hyperlinks and embedded table-like content remain operable through their actual semantics, not only readable as flattened text. The current snapshot maps nontext runs to U+FFFC and `UiaTextChildren` finds controls attached to named embedded objects; ordinary hyperlink runs do not by themselves become a distinct UIA Hyperlink provider. Identify actual accessible actions/relationships needed before choosing an extension.
- [ ] **Verify:** supported font/color/alignment/read-only attributes agree with the rendered range; mixed and unsupported sentinels are distinct. Include degenerate insertion points, mixed formatting, empty models and FindAttribute in both directions. Text2, TextEdit, TextChild and TextRange2 are absent from the provider; review their applicability to caret access, composition/IME, annotations and embedded content separately rather than requiring every optional extension. [Provider interface purposes](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-cpinterfaces)

### X5. Text-change notifications

- [ ] **Verify:** `State::Control` hooks `TextChanged` and `SelectionChanged`, but the underlying edit-mode/password setters have no corresponding UIA notification path. Test typing, same-text replacement, undo/redo, formatting-only changes, programmatic SetText, offscreen edits, caret motion and password/read-only transitions. When both Value and Text are supported, observe both applicable notification paths and query the final state. [Text event conventions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange)

## Properties, events and provider lifetime

### P1. Accessible metadata and identifiers

- [ ] **Source gaps:** review field labels noted in X1, owner HelpText noted in T2 and image-only button names. `Property` has no LabeledBy, HelpText, ControllerFor or ItemType cases. Distinguish required data for a particular control from legitimate absence; `LocalizedControlType` may use UIA's standard-role default and is not automatically a missing feature. [Property definitions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-automation-element-propids)
- [ ] **Source difference:** AutomationId is `gacui-` plus the context's allocation counter. Sibling uniqueness exists, but allocation/enumeration order is not a semantic identifier stable across application instances. Compare cold starts, lazy item enumeration and inserted controls; distinguish AutomationId expectations from RuntimeId lifetime identity. Dynamic unpredictable menu/list items may legitimately leave AutomationId empty under their role contracts. [AutomationId](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-automation-element-propids)

### P2. Property values agree with the control and pattern

- [ ] **Source gaps:** orientation is handled only for `GuiScroll`, leaving Tab/Header and applicable MenuBar orientation unavailable. ProgressBar step values are numeric instead of the role's documented NaN. Review these along with inherited popup Window capabilities, custom themes and the applicable role references in the inventory.
- [ ] **Verify:** `Property` implements only a subset of pattern-property IDs although corresponding interface getters exist. Compare `GetCurrentPropertyValueEx(..., TRUE)`, cached property requests and direct pattern getters for Selection, Grid, Table, Window and Transform. Determine which values UIA core supplies from the provider interfaces before classifying a missing switch case as a client-visible defect.
- [ ] **Source risk to verify:** `Bounds` clips to every composition ancestor; `IsOffscreen` is derived from the resulting area. Compare the complete enclosing rectangle, visible portion, programmatically hidden nodes and collapsed/offscreen nodes. Validate physical pixels across DPI/host offsets. `GetPropertyValue` does not directly provide a clickable point; determine UIA's synthesized result and whether it actually hits the intended action. [BoundingRectangle and IsOffscreen](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-automation-element-propids)
- [ ] **Source risks to verify:** synthetic rows/cells share their owning control's focus flag, qualified by selection; multiselection can mark several nodes focused. `SetFocus` ignores the result of synthetic `Select` and always returns success after `SetFocused`. Test focus at the fragment root and property level, nested editors, disabled controls and nonfocusable controls. `ElementProviderFromPoint` falls back to the current node even outside its bounds; verify outside-root points and overlap ordering. [Fragment hit-test contract](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-irawelementproviderfragmentroot-elementproviderfrompoint)
- [ ] **Source difference:** `WaitForInputIdle` validates a nonnegative timeout but returns true once dispatcher execution reaches the UI thread; it does not observe a timed idle condition. Verify its promised behavior under queued work and a busy UI thread, alongside Window state/capability getters and Move/Resize. [WaitForInputIdle](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-iwindowprovider-waitforinputidle)

### E1. Required event coverage

- [ ] **Source gaps:** `State::UpdateProperties` does not watch BoundingRectangle, IsPassword, IsKeyboardFocusable, AccessKey, WindowVisualState, WindowInteractionState, Grid row/column count, or Selection capability values. No LayoutInvalidated, MenuModeStart/End or AsyncContentLoaded emitters are present in this provider. Review each against the actual role/pattern obligations and triggering behaviors; record legitimate nonapplicability rather than inventing events for unsupported behavior. Use the inventory's role-specific Required Events sections, including [MenuBar ordering](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportmenubarcontroltype) and [Window events](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportwindowcontroltype).
- [ ] **Verify:** mutation of layout, clipping, scroll positions, theme, model values and child membership raises events for the affected semantic nodes after their readable state changes. Current `Notify` coalesces event IDs and raises `ChildrenInvalidated`; property snapshots update only nodes already created. Subscribe before first item enumeration, then change data and topology, to distinguish eager control hooks from lazy synthetic-item creation.
- [ ] **Verify:** closing and immediately destroying windows/tooltips/menus still deliver the appropriate close notification with usable event identity. The current queue skips events when `IsLive` has already become false. Avoid requiring access to a disposed control merely to issue its final lifetime event.

### E2. Selection, toggle and invocation events

- [ ] **Source gap:** `UiaSelect` reports ElementSelected for every successful selection, including AddToSelection in a multi-selection list; there is no ElementAddedToSelection emitter. It does not explicitly report the previous selected item's removal. Compare exact event type/source to resulting selection cardinality. [SelectionItem event rules](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingselectionitem)
- [ ] **Source gap:** only provider `Invoke` emits Invoked; `State::Control` does not hook ordinary button/header activation for this event. Ordinary selection callbacks mainly issue property changes or Selection_Invalidated. Exercise each command/selection through UIA, mouse, keyboard/ALT, shortcut and application model mutation and compare required events, including grouped radio/menu items. [Invoke contract](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementinginvoke), [SelectionItem events](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingselectionitem)
- [ ] **Verify:** Toggle directly changes selected/checked state; Select directly changes selection. Compare command callbacks and application side effects with ordinary user interaction, especially checkable menu commands. Invoke is queued and emits its event before running the action; test reentrancy, modal commands and self-destruction without assuming returned success means the action has completed.

### L1. Navigation, virtualization and lifetime

- [ ] **Verify:** for every returned child, parent navigation returns the original parent and sibling navigation visits each child once. Test static controls, synthesized rows/cells, retained tree nodes, popup reparenting, tab content and embedded document controls. UIA constructs its tree through these navigation relationships. [Provider fragments and navigation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview)
- [ ] **Verify:** `Control` stores `GacUI.Windows.UIAutomation` on each control to retain hooks; model callbacks shift row indices or retire nodes. Test detach/reattach before and after enumeration, cross-window moves, destruction, sort/filter, replacement rows and column rebuild. Retained providers must never target a different model item merely because an index was reused.
- [ ] **Verify:** all list items currently advertise VirtualizedItem and ScrollItem, including realized items. `Realize` expands tree ancestors and calls `EnsureItemVisible`; ordinary list enumeration creates semantic nodes for every model row. Check valid placeholder behavior, property availability, retained identity and ItemContainer search without treating the presence of VirtualizedItem as proof that every other property must fail. [VirtualizedItem conventions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingvirtualizeditem)
- [ ] **Verify:** provider methods marshal to the UI thread through the dispatcher; Invoke/Close and notifications are queued. Exercise concurrent MTA clients, callback reentrancy and shutdown while retaining providers/ranges. Confirm unsupported patterns remain undiscoverable through GetPatternProvider even though the single COM class exposes their interfaces through QueryInterface. Verify host fragment roots and `WM_GETOBJECT` behavior with ordinary and hosted windows.

### L2. GacUI architectural requirements, separately from MSDN

- [ ] **Project requirement:** composition-level automation replacement/extension is not implemented by `UiaCollectChildren`; it only traverses associated controls. Define how a custom composition can replace default semantic exposure, especially for a list/grid item, while preserving required grid/selection/header relationships. The lifetime internal property on a control is not that customization API.
- [ ] **Project requirement:** remote renderer UIA needs semantic information originating from the core plus action routing back to the core. The reviewed Windows provider queries local `GuiControl` objects; rendering DOM/HTTP automation alone does not implement these provider semantics. Record remote-mode applicability and missing transport separately from local Windows conformance.

## Verification evidence to collect later

Use the automation service first to establish rendering, compositions/elements and actual IO results; then repeat target operations through UIA on Windows. Follow the repository's [Running-GacUI guideline](.github/Guidelines/Running-GacUI.md) for launch and inspection procedures. UIA success must mean the same observable application state, not merely a successful COM return.

The existing [UIA_CppTest.ps1](Test/UIA_CppTest.ps1) and [UIA_CppTest_Metaonly.ps1](Test/UIA_CppTest_Metaonly.ps1) suites use [UIA_CppTest_Shared.cs](Test/UIA_CppTest_Shared.cs). They are useful baseline coverage for hosted and ordinary modes; they were not run for this review. `SelectCombo` searches `OwnedWindows()` for popup items, grid tests use a `Popup` helper, and text checks accept an empty Name by only excluding the value text. These tests therefore do not establish owner ancestry or accessible labeling conformance. The inspector's synthetic fixture tests validate the inspector, not every GacUI provider contract.

For each checkbox, retain the source revision, application/template/mode, raw/control/content tree paths, provider/property values, exact HRESULTs, event type/source/order and the resulting rendered/application state. Mark an item resolved only with a reason: implementation confirmed, discrepancy reproduced, documentation ambiguity resolved, or conditional requirement shown inapplicable.
