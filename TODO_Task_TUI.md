### Controller lifetime, scheduling, and services

- `vl::console::TUI::Start` is blocking and owns the calling thread. Install the TUI callback first, then initialize the GacUI controller/resource-manager/application stack from `ITuiCallback::Starting`, after terminal takeover. The native window service's `Run` pumps `TUI::RunOneCycle` on that same thread. This supports the requested immediate takeover before `Show` without creating a second UI thread or attempting a second active `TUI::Start`.
- Wrap `TuiControllerBase` with the existing `GuiHostedController`, and wrap the TUI graphics resource manager with `GuiHostedGraphicsResourceManager`, following `RendererMainDirect2D` in `Source/PlatformProviders/Windows/Direct2D/Renderers/GuiGraphicsWindowsDirect2D.cpp`. Publish `GetTuiApplication()` before application utilities initialize, keep it valid through their finalization, and clear it before destroying its owner. Non-TUI setup leaves it null.
- Set up the initial terminal size before entering the nested application loop: the initial `BufferSizeChanged` from `TUI::Start` normally follows `Starting`, so it cannot be the only initialization path when `Starting` runs the application. On normal return, finalize the hosted/application stack, request TUI stop, uninstall listeners after `Start` returns, and restore globals in ownership order.
- Reuse existing non-TUI services only where their dependencies remain valid. In particular, `WindowsController::Run` normally drives its asynchronous queue and Win32 timer/message delivery; returning its `AsyncService` or `InputService` unchanged does not make those facilities run inside a TUI loop. Reuse the common async-service implementation and drive its queued/delayed work from the owner-thread TUI timer. Route the same timer to GacUI global-timer callbacks for rendering and caret blinking. Do not run a competing Win32 window loop or call TUI from worker threads.
- Audit service delegation individually: retain image decoding and clipboard/resource facilities that work without a graphics window; expose only `TuiFont` at size 1; supply cell-based screen information, key state/input behavior, and window services through the TUI adapter. Keep platform handles and any necessary Windows service plumbing in `Source/PlatformProviders/Windows/TUI`, with Windows file suffixes and guards. Services that require an HWND, such as clipboard notifications, need a Windows-only service window and nonblocking message dispatch integrated with the TUI pump; this is not another `INativeWindow`. Do not pass a TUI window to a service that assumes `WindowsForm`.
- `ImageService` can in fact be called while decoding resource images. Its availability permits loading those assets; it does not make `GuiImageFrameElement` or document image runs renderable. `AutomationService` stays null and the demo starts no automation endpoint.
- Forward key actions through `KeyDown`/`KeyUp` and text through `Char`, preserving native `wchar_t` units, modifiers, repeat flags, mouse buttons, cell coordinates, and signed wheel deltas. Do not generate a second text insertion from `KeyDown`. Keep terminal Alt separate from OS Super, and do not assume that future POSIX backends report key-up or every modifier.

### Rendering and text layout

- Treat `Source/UnitTestUtilities/GuiUnitTestProtocol_Rendering_Document.cpp` as a behavioral reference for simple layout, not a ready TUI metrics implementation. Its `GetCharacterWidth` uses fractional font-scaled widths and its lines add four pixels of spacing. TUI text rows are one cell high, and scalar widths come from `TUI::MeasureChar`.
- Share scalar decoding and cell-width/layout rules between labels and paragraphs. Decode UTF-16 pairs on Windows while preserving GacUI's native-string offsets for text ranges and caret APIs. Never measure/draw isolated surrogate units. Zero-width/non-printable scalars do not become invalid standalone cells; CR/LF and tabs need layout handling rather than raw `PrintChar` calls. Keep the document unchanged when text cannot fit: a width-two scalar at a one-cell viewport is clipped, not split or dropped from the model.
- Support label alignment, multiline/wrap behavior, ellipsis, and wrap-sensitive minimum size. Support paragraph style/color/background ranges, wrapping, alignment, all caret navigation/hit-test APIs, selection, and caret blinking. Font family, size, and antialias settings do not affect cell metrics; bold, italic, underline, and strikeline remain meaningful and map to `TuiTextStyle` after the dependency refresh.
- Preserve valid caret boundaries around UTF-16 pairs, width-two cells, CRLF, and inline objects. `GetCaretBounds` retains the interface's zero-width logical rectangle, while the renderer draws a visible cell-based caret overlay. Embedded non-image compositions still require inline-object sizing, callbacks, hit testing, and relayout. Document image runs remain unsupported: `GuiDocumentImageCache::GetImageElement` creates a `GuiImageFrameElement` even without an explicit `<ImageFrame/>` in XML.
