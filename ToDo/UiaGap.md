Evidence labels used below:

- **Source gap:** a concrete current implementation path and a conflicting requirement or accepted-operation lifetime are identified. The proposed runtime reproduction has not been executed in this report.
- **Conditional source gap:** the contradiction depends on a specified application/template configuration; do not generalize it to default controls.
- **Unproven candidate:** a necessary premise or Windows interleaving has not been established. This is not a confirmed P2.
- **Verification gap:** an applicable contract needs targeted evidence; missing evidence alone is not a code defect.
- **Implemented path:** source contains the behavior. Historical passing tests are attributed to their original revision and do not prove every current configuration.

## Contract interpretation and implemented foundation

Microsoft's [control-type requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-controltypesoverview) cover tree structure, properties, patterns and events together. A supported interface alone does not establish conformance. Required patterns must exist; conditional patterns apply when the corresponding behavior exists. Typical tree diagrams are not blanket prohibitions on additional meaningful wrappers. Use the specific control/pattern contract when general descriptions conflict.

The provider exposes 19 pattern interfaces: Invoke, Toggle, Selection, SelectionItem, ExpandCollapse, Value, RangeValue, Scroll, ScrollItem, Grid, GridItem, Table, TableItem, ItemContainer, VirtualizedItem, MultipleView, Window, Transform and Text. `GetPatternProvider` and availability properties gate them by current behavior. QueryInterface alone is not the availability test.

The following implementation should be preserved:

- Both native renderers install the listener for ordinary and hosted applications. Window discovery records HWNDs without materializing COM providers; requests and subscribed events create providers as needed. Accessibility metadata alone does not start whole-tree observation.
- The provider slot is non-owning and locked against final Release. Patterns share provider ownership; text ranges retain their originating and embedded attachments. Control/model event tokens are detachable, removal retires subtrees synchronously, and disconnect is deferred.
- `GuiWindow::ChildCompositionUpdated`, declared in [GuiWindowControls.h](../Source/Application/Controls/GuiWindowControls.h), reports successful direct insertion/removal/reordering with parent/child information. Removal captures the original window and reports the still-live child synchronously. UIA must never queue those raw event pointers. The implementation is in [GuiGraphicsComposition.cpp](../Source/Application/GraphicsCompositions/GuiGraphicsComposition.cpp).
- Known combo/menu/gallery/tooltip popups have logical owners. Native popups retain their HWND host provider; hosted popups share the host fragment. This follows Microsoft's explicit [Assigning a New Parent procedure](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-serversideprovider#assigning-a-new-parent). The earlier R2-04 claim that this necessarily violates fragment boundaries was withdrawn.
- Default grid editors replace visualizer exposure beneath the same logical cell; selected tab content belongs beneath its TabItem; logical model nodes preserve identities across ordinary visual recycling. Focus and selection are separate operations.

### COM ownership agreed in this review

Count Windows/UIAutomationCore as a client along with external tools. A balanced final `IUnknown::Release` at total count zero is the destruction signal. An external tool releasing its own pointers does not establish that the total count is zero. The provider does not need to identify the owners. [IUnknown::Release](https://learn.microsoft.com/en-us/windows/win32/api/unknwn/nf-unknwn-iunknown-release)

Windows can hold provider references in its raised-event map for accessibility interoperability. Destroyed HWNDs require `UiaReturnRawElementProvider(hwnd, 0, 0, nullptr)` cleanup. A surviving reference is compatible with Windows ownership, but tracing is required to attribute a particular reference; it is not automatically proof against a GacUI leak. [HWND map cleanup](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiareturnrawelementprovider)

Control attachment lifetime remains separate: detach observation and invalidate access when the underlying UI is removed, even if COM owners remain. Retire before deferred disconnection and never return the retiring provider to reentrant WM_GETOBJECT. [UiaDisconnectProvider](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiadisconnectprovider)

Subscriptions are another counted resource. With `IRawElementProviderAdviseEvents`, matching additions/removals must keep the events/properties requested by remaining clients active. Neither global client presence nor one tool's exit replaces this accounting. [Subscription contract](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nn-uiautomationcore-irawelementprovideradviseevents)

## Open findings from this session

G01-G04 retain the four open P2 source-review findings. U01 records the fifth original finding with its later correction. None is claimed runtime-reproduced.

### G01: Pending action ownership

**Status: source gap, P2.** `WindowsUIAutomationProvider::Queue` retains a semantic node but no COM attachment, while `WindowsUIAutomationContext::Collect` retains nodes only for providers or subscriptions. With no subscriptions, a cleanup for provider B can already be posted; a synchronous Invoke on A can run first and post its action; all COM owners of A, including Windows, can then release before B's cleanup executes. Collection retires A, and its accepted action fails the queued `IsLive` guard. [Queued action](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationProvider.Windows.cpp#L116), [collection](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationState.Windows.cpp#L168)

The user sees a successful invocation/close request with no subsequent effect. Windows retention can mask the trigger; it does not express ownership for GacUI's own pending action. Retain the attachment until the action completes, or include pending actions in collection's required set. Preserve legitimate cancellation when the actual control is removed or disabled. Microsoft requires Invoke to return asynchronously, including when it opens modal UI. [Invoke](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-iinvokeprovider-invoke)

**Acceptance:** deterministically arrange the cleanup/action ordering without subscriptions, observe the actual final COM release rather than assuming client disposal caused it, and require the accepted action exactly once while the control remains valid. Also test actual control destruction before dispatch.

### G02: Focus-only clients miss undiscovered logical targets

**Status: source gap, P2.** The new selection-subscription guard prevents seeding calendar-day nodes when only focus events are requested. On first focus, the day hook creates its logical node with a focus snapshot already true; the queued comparison sees no transition. The raw day button intentionally reports no focus. A preselected grid cell has a similar discovery gap while the grid suppresses container focus. [Selection guard](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationState.Windows.cpp#L520), [day hook](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationState.Windows.cpp#L296), [logical focus](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L490)

A screen reader can miss a newly focused date/cell even though visual focus moves. Track logical focus targets and their previous state independently of selection-event subscriptions, without eagerly constructing COM providers. Existing tests that discover the day before subscribing do not cover this ordering. [Calendar focus requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportcalendarcontroltype)

**Acceptance:** subscribe only to AutomationFocusChanged before any day/cell traversal; move focus through application input; require the exact logical target's event and agreement with GetFocus. Do not make focus select a different item. Require an active foreground desktop for actual desktop-focus delivery.

### G03: Subscription changes consume pending notifications

**Status: source gap, P2.** Every AdviseEvent addition/removal invokes `RefreshObservation`, which refreshes all snapshots with event raising disabled. If a change is queued and another subscription call reaches the UI thread first, the old value/selection is replaced. The queued notification then sees no difference. [RefreshObservation](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationState.Windows.cpp#L135), [AdviseEvent](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationProvider.Windows.cpp#L68)

An existing client can retain stale state or miss an announcement when another client connects or changes subscriptions. Initialize newly watched state without overwriting pending baselines for existing subscribers, or deliver the applicable pending differences before rebasing. [Multiple-client subscription accounting](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nn-uiautomationcore-irawelementprovideradviseevents)

**Acceptance:** client A listens, the UI changes, client B adds/removes a subscription before notification dispatch, and A still receives the required change with correct source/payload. Cover property, focus and selection tracking, plus B's independent removal.

### G04: Radio-group identity depends on insertion order

**Status: source gap, P2.** `UiaRadioGroup` chooses the first mutex member in the current control-tree traversal and keys the group by that member. Insert a same-group radio into an earlier container: existing radios now point to a new group, while the original retained group stays live and enumerates the same members. [UiaRadioGroup](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L59)

Automation clients can retain a live group that no longer appears in its parent's children. Preserve the existing represented group identity, keyed by the mutex controller with an explicit controller/attachment lifetime, rather than recomputing identity from traversal order. This extends the earlier fixed mutex-group semantics. [RadioButton](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportradiobuttoncontroltype), [provider tree navigation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview)

**Acceptance:** retain the group, insert/move members before its original anchor, and check RuntimeId, SelectionContainer, reciprocal parent/child navigation and membership. Separately verify group/controller removal and cross-window attachment changes.

### U01: Subscription cleanup after final release and retirement

**Status: unproven candidate; withdrawn as a confirmed P2.** Final Release clears the provider slot and queues cleanup that later resolves `target->context`. If retirement/collection clears that context first, and the provider still had recorded subscriptions, the callback could skip decrementing aggregate counts. [Release callback](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationProvider.Windows.cpp#L20), [retirement](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationState.Windows.cpp#L628)

The necessary premise is **total COM count zero while subscriptions remain recorded**, not merely an external tool releasing pointers. This review has not established that conforming UIAutomationCore allows that ordering. Normal unsubscription before final release defeats the scenario. Counting Windows as a client therefore changes this finding's confidence; do not list it as a demonstrated leak or as the cause of the reported crash.

**Acceptance:** trace AdviseEventAdded/Removed, every relevant final Release, retirement and queued cleanup during real subwindow destruction. If the premise cannot occur under the supported contract, close the candidate with that evidence. If it can, retain independent context/subscription cleanup state and verify aggregate observation returns to the proper level.

## Additional gaps from the Microsoft control comparison

These are current source/contract findings, not a claim that all old review findings remain unfixed. Conditional configurations and required follow-up evidence are explicit.

### G05: Empty positions in a spatial grid cannot be queried

**Status: source gap.** `UiaSpatialGrid` rounds dimensions up for multi-column arrangements; `GetItem` accepts coordinates inside those dimensions and then returns E_INVALIDARG if the corresponding linear item index is beyond the model count. Microsoft requires an element for an empty grid cell, including ragged layouts, so its ContainingGrid remains available. [Grid contract](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementinggrid), [dimensions](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L107), [GetItem](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationPatterns.Windows.cpp#L58)

An automation client iterating the advertised rectangle fails on the last partial row/column. Define empty-cell identity, coordinates, spans and ContainingGrid consistently with the exposed grid. Test five items in three columns, the column-major equivalent, one item, empty lists, and resize-driven capacity changes. Truly out-of-range coordinates must still fail.

### G06: Layout and asynchronous-content events lack emission paths

**Status: source gap for applicable layout transitions; application integration gap for asynchronous loading.** The bridge has no `UIA_LayoutInvalidatedEventId` or `UIA_AsyncContentLoadedEventId` emission. Structure invalidation and property changes do not implement those distinct events. Calendar, DataGrid and Window requirements include layout invalidation; List requires it when layout can change. Window and Pane requirements include asynchronous-content reporting. [Calendar](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportcalendarcontroltype), [DataGrid](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportdatagridcontroltype), [List](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportlistcontroltype), [Window](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportwindowcontroltype), [event meanings](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-event-ids)

Clients subscribed to those events receive no corresponding signal. Add subscribed layout notifications for relevant child-layout changes, with deliberate batching and source identity. Define how an application reports real asynchronous loading progress/completion; the provider cannot infer download semantics from arbitrary property changes. Test calendar navigation, grid/list relayout and a controlled asynchronous content load, including no listeners and unsubscribe. Do not fabricate async-loading events for static controls.

### G07: Standalone scroll controls retain ScrollBar semantics

**Status: conditional source gap with existing showcase examples.** `Role` selects ScrollBar versus Slider from the theme name, so standalone HScroll/VScroll controls remain non-content ScrollBars. Microsoft requires standalone bars that act as value selectors to fulfill Slider semantics. [ScrollBar requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportscrollbarcontroltype), [role dispatch](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L377), [RepeatTabPage examples](../Test/Resources/App/FullControlTest/RepeatTabPage.xml#L84)

A content-view client can miss an application value selector. Determine semantic use independently of visual skin: preserve ScrollBar for a scrolled container's infrastructure and Slider for a standalone selector. Verify both axes, content membership, orientation, RangeValue and keyboard behavior. RangeValue on a ScrollBar is conditional; Scroll belongs on the scrolled container, never directly on the ScrollBar.

### G08: MenuBar keyboard focus is not represented

**Status: source gap.** `IsFocusable` uses only the control's own focus composition; `GuiMenuBar` has no such target. It therefore reports false and its UIA SetFocus is rejected, whereas Microsoft's MenuBar contract requires keyboard focusability through the menu's contained controls. [MenuBar requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportmenubarcontroltype), [IsFocusable](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L484), [GuiMenuBar](../Source/Controls/ToolstripPackage/GuiMenuControls.cpp#L240)

Define the UIA focus target using GacUI's existing menu/Alt navigation model. Test SetFocus and Alt entry, the resulting logical focus, keyboard navigation and focus events without invoking a command merely to focus the menu. Preserve existing MenuModeStart/Open/Close/End ordering.

### G09: A custom calendar template can lose required patterns

**Status: conditional source gap.** Every `GuiDatePicker` receives Calendar role, but Grid/Table/Selection and day/header discovery depend on finding `GuiCommonDatePickerLook` in its compositions. A functioning custom date-picker template without that concrete look can expose Calendar without its mandatory Grid/Table. [UiaCalendar](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L96), [Role/Supports](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L354), [Calendar requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportcalendarcontroltype)

Make the semantic date/header contract independent of that concrete look, or explicitly define/enforce the supported accessible template contract. Test a valid replacement template and retained day/header references during replacement. The default six-by-seven look already implements Grid/Table; optional paging Scroll is not being reclassified as an unconditional missing pattern.

### G10: Rich ListItem templates expose content children

**Status: conditional source gap.** Generic list-item traversal exposes template controls; the property implementation marks ordinary nested labels/buttons/editors as content. Microsoft's ListItem contract explicitly requires zero content-view children, while allowing presentation children in control view. [ListItem requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportlistitemcontroltype), [item children](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L583), [content membership](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationProvider.Windows.cpp#L209)

Simple text-list items do not exercise this path. Define content filtering for presentation subelements and an appropriate semantic model for genuinely nested interactive data, preserving accessible actions rather than blindly hiding them. Test a generic template containing Text and interactive controls with separate raw/control/content walkers; verify item count and selection identity.

### G11: Synthetic page-body panes have no meaningful name

**Status: source gap.** `Kind::TabContent` is always a content Pane but `Name` always returns an empty string. The Pane contract requires a meaningful title. [Name/Role](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L321), [Pane requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportpanecontroltype)

A user navigating panes hears an unnamed region. Supply page-derived or explicit semantic metadata while preserving the selected TabItem's content ownership and hit testing. Also audit fallback Pane nodes: purely visual layout objects should not become content panes, but this does not justify removing all wrappers. Verify distinct page titles, renaming and selected-page changes.

### G12: Explicit labels duplicate content-view information

**Status: source gap.** `SetWindowsUIAutomationLabel` makes a target's Name come from its label, but the label remains a content Text node unconditionally. Microsoft's Text content rule distinguishes independent information from information already supplied by another control's Name. [Text requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporttextcontroltype), [content property](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationProvider.Windows.cpp#L209), [name resolution](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationSemantic.Windows.cpp#L299)

Content-view readers can encounter the same label twice. Preserve raw/control-view label identity and LabeledBy while filtering redundant content according to the explicit association. Test the existing Account name label/edit fixture using a content walker, then change/remove the association and dispose the label. Avoid suppressing independent text merely because its string happens to match another Name.

### Cross-cutting pattern and property checks

- [SelectionItem](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingselectionitem): reject conflicting single-selection additions atomically, respect required selection, and distinguish Selected/Added/Removed events. Focusing and scrolling must not silently select. The implemented paths require burst/model-replacement coverage under G03.
- [Text/TextRange](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange): retain selection modes, degenerate caret/empty-visible ranges, matching enclosing elements, valid movement results, attributes, geometry and embedded-object identity. Multi-edit tracking, bidi/combining clusters and clipping remain verification gaps, not automatic defects merely because prefix/suffix adjustment is used.
- [VirtualizedItem](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingvirtualizeditem) and [ItemContainer](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingitemcontainer): verify search, realization, identity and unavailable results without requiring every realized item to lose its richer provider. Semantic enumeration may still allocate nodes for the entire model; COM laziness alone does not prove bounded memory or traversal cost.
- [Automation properties](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-automation-element-propids): compare direct properties with pattern getters and actual UI state. Check label disposal, dynamic shortcuts/tooltip replacement, header activation, disabled/modal transitions and provider-valued properties. Application-supplied AutomationId or an empty dynamic ID is supported; RuntimeId is a separate lifetime identity.
- Conditional item metadata gap: [property dispatch](../Source/PlatformProviders/Windows/UIAutomation/WindowsUIAutomationProvider.Windows.cpp#L180) supplies ItemStatus for headers but no general ItemType or item-status mapping. Custom list/tree items with meaningful type icons or status changes need semantic metadata and corresponding notifications; plain text items do not establish that requirement. Include these cases alongside custom item Invoke/edit behavior in the template audit.
- Newer Text2/TextRange2/TextEdit/TextChild, Selection2, Transform2, Dock, drag/drop and custom navigation capabilities are not advertised. Record an explicit target-version/behavior requirement before treating each as mandatory missing support. Standard LocalizedControlType fallback can be supplied by UIA; lack of a custom getter is not itself a defect.

### Historical runtime evidence and limits

The [demand-refactor investigation at a6e3f691](https://github.com/vczh-libraries/GacUI/blob/a6e3f691424995b554efd6e2513b35e0e7be140c/.github/TaskLogs/Copilot_Investigate.md) records zero providers/ranges/semantic observation in its controlled no-client operations; 25 clean fresh-process lifetime runs across native/hosted and GDI/Direct2D combinations; four additional concurrent runs; and a final UnitTest result of 93 files / 1,786 cases without an appended leak report. These are reported prior results, not reruns for this document or proof against the newly identified interleavings.

The same record reports ProgressAndAsync mean maximize/restore times of 644.85/639.27 ms before versus 296.36/288.25 ms after with no client, and 3494.34/2536.64 ms before versus 3619.50/3873.81 ms after with active traversal/subscriptions. The controlled active-client case therefore remained slower. The released-client phase improved, but some providers still had references; the log's infrastructure attribution is plausible, not a trace identifying every owner.

The reported create/delete-child-then-close-app crash was not reproduced. Its cause is still unknown. Prior results explicitly leave nondefault DPI, a second monitor and actual desktop-focus delivery unverified in that environment. Earlier default-desktop performance measurements were contaminated by unsolicited subscriptions and must not substitute for the isolated baseline.

## Verification backlog and acceptance

Use [Running-GacUI.md](../.github/Guidelines/Running-GacUI.md), [Building.md](../.github/Guidelines/Building.md), [Debugging.md](../.github/Guidelines/Debugging.md) and [Project.md](../Project.md). Subsequent implementation must use repository build/execution wrappers; reflected API changes require the prescribed Win32/x64 metadata generation and testing. C++ changes require configured UnitTest and post-summary leak inspection. This documentation-only consolidation does not require a rebuild.

Existing clients are [UIA_CppTest.ps1](../Test/UIA_CppTest.ps1), [UIA_CppTest_Metaonly.ps1](../Test/UIA_CppTest_Metaonly.ps1), [UIA_CppTest_Shared.ps1](../Test/UIA_CppTest_Shared.ps1), [shared assertions](../Test/UIA_CppTest_Shared.cs) and [native lifetime assertions](../Test/UIA_Lifetime.cs). The shared driver has All/Review/Review2/Review3/Transitions/Lifetime scenarios; inspect its current parameters before running. Playground fixtures belong in authored XML. Select ordinary/hosted and GDI/Direct2D explicitly and assign distinct `/AsPort` values to avoid collisions.

Preserve the original integration checks: composition notifications occur once per successful direct change, never for failed/detached/no-op changes; populated-subtree attachment raises one notification; cross-window reparenting reports removal then insertion with valid synchronous arguments. Reflection and teardown need coverage. `/AsPort` accepts one decimal value in `1..65535`, defaults to `8888`, and rejects malformed/duplicate values before listener startup. It changes only automation endpoints; remote protocol sockets remain on `8888`, including shared-versus-separate MiniHTTP endpoint ownership.

1. **Focused findings first.** Add the minimal reproducer/acceptance test for each G01-G12 condition and the conditional gaps in the control/property matrix before claiming its repair. G01 needs controlled release/queue ordering; G02 must avoid premature traversal; G03 needs interleaved clients; G04 needs a live retained group during insertion. U01 needs proof of its prerequisite before a fix is justified.
2. **Ownership and no-client baseline.** Without inspection tools creating accidental demand, open/mutate/resize/remove/reinsert controls and secondary windows. Count COM providers/ranges separately from semantic nodes, hooks, snapshots and queued work. Verify no eager work. Then acquire/query/release using native COM pointers, explicitly balance all references, and trace infrastructure-held references instead of equating tool exit with final destruction. Include provider-valued labels and retained ranges.
3. **Retirement and shutdown.** Retain elements, patterns and text ranges across removal, reinsertion, cross-window moves, model replacement, template refresh, child-window deletion and app shutdown. Require unavailable responses while the server remains alive, and bounded UIA/RPC failure after exit. Repeat at least 25 fresh child-create/delete/shutdown cycles under the debugger, including pending notifications, off-thread final release and concurrent readers. Keep the original crash investigation separate from unrelated HTTP startup failures.
4. **Tree, actions and roles.** Record raw/control/content trees, RuntimeIds, parent/sibling reciprocity, pattern availability, exact HRESULTs and actual UI effects. Cover custom list/tree/grid/calendar/ribbon templates, selected/offscreen grid editing, same-count model replacements, sorting/filtering, row/column rebuilds, popup owners and hit testing. Verify DataItem row wrappers: they currently lack GridItem/TableItem while their cells provide them; determine the appropriate row/cell model and obligations before treating the wrapper itself as a confirmed defect.
5. **Keyboard focus and metadata.** Keep focus independent from selection. Test calendar/grid event-only cases and menu entry, then reconcile ordinary ListItem/TreeItem focusability with actual container-held keyboard navigation. The ListItem recommendation is not proof that every selected item should report focus. Supply meaningful labels for application editors, combos, images and textless drawn tooltips; test label disposal, title changes, localization, duplicate content filtering and shortcuts.
6. **Text and error boundaries.** Cover ViewOnly/Selectable/Editable, disabled/modal controls, masked transitions, retained ranges, empty text, exclusive endpoints, surrogate pairs, combining characters, bidi, mixed fonts/paragraphs, clipped glyphs, multiple edits and independent embedded text stores. Compare direct password Value-property reads (`S_OK`/empty variant in source) with pattern reads (`E_ACCESSDENIED`) at the actual client API: record the documented error expectation without calling the empty result a plaintext leak. Check fractional RangeValue input and partial two-axis Scroll failure against exact contracts before classifying defects.
7. **Events with independent clients.** Subscribe before discovery; verify source, payload, order and final state, not just event totals. Include property/focus/selection subscriptions separately and together, one client leaving while another remains, newly inserted descendants, layout/async events, menu nesting, document links, modal WindowClosed and immediate destruction. Use genuine foreground input for desktop focus; HTTP-injected input tests application routing only.
8. **Scale and active-client performance.** Measure large list/tree/grid navigation, ItemContainer searches, retained semantic-node counts, callback accumulation and document text-range costs. Repeat ProgressAndAsync after the same completed document load in equivalent Debug builds with no client, active clients and released clients. Fix DPI/window sizes/content, assert real maximize/restore transitions and time completed UI work. The tutorial must link the updated provider through its release workflow. No universal latency threshold or active-client speedup has been established.
9. **Display and capability applicability.** Run multiple monitors, nondefault DPI and DPI changes, RTL/bidi, occlusion, partly offscreen windows, horizontal scrolling, custom toolbar/tab overflow, and interactive tooltips. Explicitly record unavailable environments and unsupported capabilities. Re-run the relevant ordinary/hosted renderer matrix and wider regression suite after focused fixes.

Each completed item should record the source revision, fixture/template, renderer/hosting mode, subscription scope, ownership state, exact client result/event, application state and debugger outcome. Passing existing broad suites alone cannot close a gap they do not exercise.

## Separate GacUI architectural backlog

These preserve L2 and the later D/V design discussion. They are not unimplemented mandatory Microsoft patterns for the current local Windows provider.

1. **Composition-level semantic source.** Attach an optional semantic source to a `GuiGraphicsComposition`, with explicit augment/replace behavior, stable application identity, roles/capabilities/properties, children and actions. Include the root composition. Reject duplicate/cyclic identities. The current control-lifetime internal property and four Windows metadata helpers are not this extension API.
2. **Model-owned identity and obligations.** Custom item presentation must preserve or explicitly implement row/column coordinates, selection containers, headers and model identity. Bound lifetime by composition attachment plus model generation; recycled template pointers cannot be persistent identities.
3. **Platform-neutral semantic model.** Factor semantic queries/actions into a core model with logical IDs and revisions. Keep COM, HWND/DPI and UIA event adaptation in Windows. Other renderers must not infer accessible names/actions from drawing elements or HTTP DOM inspection.
4. **Remote protocol.** Extend the authored protocol schema with negotiated semantics, full snapshots, revisioned deltas, correlated action requests/completions and connection epochs. Core-to-renderer messages carry state/completions; renderer-to-core actions need explicit correlation under the existing channel direction. This is currently missing, rather than supplied by the local listener.
5. **Remote consistency and retirement.** Apply deltas atomically before local notifications; reset from a full snapshot on reconnect and retire the old epoch. Validate action generation/capability/enablement again in the core. Do not transport passwords, cached old plaintext or live pointers. Synchronous COM reads use coherent renderer state; actions must not block the renderer UI thread awaiting the core.
6. **Shared contract verification.** Reuse semantic fixtures for native, hosted and remote adapters. Cover reconnect/replacement, stale/out-of-order requests, multiple clients, disabled/modal state and shutdown. Generate protocol code through Metadata_UpdateProtocol and preserve actions/lifetime messages outside lossy repeat-drop filtering.

Design references: [remote core architecture](../.github/KnowledgeBase/KB_GacUI_Design_RemoteProtocolCoreArchitecture.md) and [renderer/serialization architecture](../.github/KnowledgeBase/KB_GacUI_Design_RemoteProtocolRendererAndSerialization.md).
